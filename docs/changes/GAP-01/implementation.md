## The stop: next 16.4.3 changes every page's HTML (plan 5.2, R-1)

Noise floor: the base (`git archive 6470fac`, `npm ci`) was built twice with
`CONTENT_SOURCE=snapshot PUBLIC_SITE_URL=https://digitalhub.com.eg`, both
exit 0. `diff -r out-base-1 out-base-2` → exit 0, **no differences** (the
floor is empty).

`diff -rq out-base-1 /home/user/DH-WEBSITE/website/out` → exit 1, 28 lines:
every HTML page differs (`404.html`, `500.html`, `about.html`, …,
`services/outsourcing.html`); no file added or removed; no non-HTML file
differs. For each of the 29 HTML files, the base and branch are identical
once one element is deleted from the branch page. That element, from
`about.html`, just before `</body>`:

```html
<script id="_R_">(globalThis["TURBOPACK"] || (globalThis["TURBOPACK"] = [])).push({"otherChunks":["static/chunks/2rxg2vmc3djp4.js","static/chunks/3rwt2kk_qwk5n.js","static/chunks/3r-o8o3vf8kuq.js"],"runtimeModuleIds":[56944]});</script>
```

Why the guards missed it:

- `website/src/build/strip-runtime.ts` removes `/_next/` script tags, `/_next/`
  script preloads, `self.__next_f` scripts and boundary markers. This new
  inline script matches none of them. The strip counts are the same on base
  and branch (203 runtime script tags, 29 preloads, 58 payload scripts, 10
  `_next/` files deleted).
- `runtimeTracesIn` looks for `/_next/`, `__next_f` and React boundary
  markers. The script names its chunks as `static/chunks/…` with no `/_next/`
  prefix, so no trace is found; `check-output.ts` reuses the same function
  and prints "Static HTML: no page contains Next's client runtime".
- The chunks it names are not in `out/` (`out/_next/` is deleted), so in a
  browser it only creates `globalThis.TURBOPACK` and pushes an object. It is
  still a new inline script on every page (the site's content security policy
  is report-only today, so this would at least produce a violation report
  wherever inline script is not allowed), and it is Next's client runtime,
  which the site's design says must not ship.

This is the plan's stop rule (5.2 step 3: "Any such change to a page's HTML
structure, head tags, design set or JSON-LD stops the change and returns it
to the architect"; R-1). The obvious fix, a new removal and a new trace in
`website/src/build/strip-runtime.ts` (with a test fixture from the 16.4.3
export in `website/test/strip-runtime.test.ts`, whose comment still says
"Next 16.3.6"), changes website build source and tests outside the plan's
Scope (section 4 lists `strip-runtime.test.ts` as out of scope unless the
export changes, "in which case the developer stops and the change returns to
the architect"). So I did not make it.

Suggestions for the architect, not decisions: (a) extend the removals and
`runtimeTraces` to cover the `_R_` Turbopack bootstrap (for example a trace on
`TURBOPACK` and on `static/chunks/`), with a red test first that feeds the
16.4.3 page shape to `stripRuntime`/`runtimeTracesIn`; (b) consider whether
this is a G1 guard gap worth its own red-test commit (B-6) inside GAP-01, since
the fail-closed check let Next's runtime through; (c) after that, the noise
floor and base-vs-branch diff must show zero HTML differences, then the
browser checks in 5.3 run.

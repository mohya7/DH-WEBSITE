# Engineering standards

This repository follows the AI-Assisted Delivery Standard (Mohamed Elbadry,
18 October 2026), adapted to this project. Every rule has an id, how it is
enforced, and its status. What is specific to this project is in
`docs/PROJECT_PROFILE.md`. The first measurement is
`docs/quality/baseline-2026-10-27.md`.

`AGENTS.md` (and its copy `CLAUDE.md`) keeps the working rules: sections,
coverage tables, the builder and checker rotation, ports, databases, and
sources. Where `AGENTS.md` and this file both speak, the stricter rule applies.
A rule changes only through an ADR in `docs/adr/`.

Status: **Met** — enforced in CI or by a test today. **Partial** — some of it
is enforced; the rest is named. **Gap** — not enforced yet; the step that adds it
is named. **N/A** — does not apply until the named phase.

## 1. Principles

| Id | Rule | Enforced by | Status |
|---|---|---|---|
| P-1 | The integration branch, and later the deploy branch, changes only through a merged, reviewed pull request. | Integrator (`AGENTS.md`); deploy guard from Phase D | Partial: no branch protection recorded; no deploy yet |
| P-2 | Gates land before refactors. Existing debt is baselined and may only shrink. | Each gate's baseline file (section 6) | Partial: security gate only |
| P-3 | Strangler, never big-bang. The old site stays deployable until the new one has run without incident. | `docs/business-analysis.md` section 16 | Met |
| P-4 | A failing test exists before the fix. Attack tests come from the design, before the code. | Review; red-test commit before its fix (B-6) | Partial: by review only |
| P-5 | Fail closed. A check that cannot decide blocks. | Security gate (`gate.mjs` fails on unknown or malformed input); API fallback policy requires an authenticated user | Met |
| P-6 | Never weaken a gate, guard or test to make something pass. A conflict is resolved by a recorded decision. | Review; golden copies of the security workflow | Partial |
| P-7 | Only the owner decides exceptions and behaviour changes. Their words are quoted exactly, with the date. | `docs/deferred-items.md`; PR template | Met from this change |
| P-8 | Evidence, not claims. Anything not verified is written NOT RUN, with the reason and the CI job that covers it. | PR template; `AGENTS.md` coverage tables | Met |

## 3. Quality gates

One rule for all of them: a gate that cannot run fails. A new gate reports for
seven days from its merge (a `*_BLOCKING_FROM` date in the workflow), then
blocks, unless it replaces protection that already existed. Tools are pinned by
exact version or checksum. Each gate has a test that proves it still fires.

| Id | Gate | Threshold | Enforced by | Status |
|---|---|---|---|---|
| G-1 | Secrets scan | 0 findings | gitleaks 8.30.1 (sha256-checked) on pull request commits and full history, `security.yml` | Partial: the weekly run never fires (baseline F2) |
| G-2 | Build and unit tests, every package | 0 failures | `ci.yml`: API Release build and tests; website and Studio Vitest; Studio Playwright | Met |
| G-3 | Database tests on the production SQL Server version | 0 failures | `ci.yml` SQL Server service | Partial: production version not recorded; image tag floats |
| G-4 | Migrations apply from empty and from the previous schema | exit 0 | `ci.yml` applies from empty | Partial: previous schema not tested |
| G-5 | Lint (TypeScript, C#) | 0 new issues; existing in a shrink-only baseline | — | Gap: step 4a, 4b |
| G-6 | Type check | 0 errors | `tsc` strict in website and Studio; C# nullable | Partial: C# warnings not counted (step 4b) |
| G-7 | Formatting | 0 unformatted new files | — | Gap: step 4c |
| G-8 | Coverage | ≥ 80% of changed lines; a global floor that only rises | — | Gap: step 4d |
| G-9 | Duplication | ≤ 3% of changed code | — | Gap: step 4e |
| G-10 | Static security analysis | 0 unlisted findings | Semgrep 1.180.0 (ERROR fails), `security.yml`; CodeQL when enabled | Partial: CodeQL skipped on a private repository |
| G-11 | Dependency vulnerabilities, every lockfile, full tree including dev | 0 unlisted or expired | `run-npm-audit.sh`, `run-dotnet-audit.sh`, `known-findings.json` | Partial: production tree only; no expiry; fails today (baseline F1, F3, F4) |
| G-12 | Container images | 0 unlisted High or Critical | — | N/A: no images; IIS |
| G-13 | Workflow lint | 0 findings | Golden copies for `security.yml` | Gap: actionlint on every workflow, step 3 |
| G-14 | Deploy guard self-test | all pass | — | N/A until Phase D |
| G-15 | Tools and actions pinned exactly | — | gitleaks, Semgrep exact | Partial: actions on major tags, `mssql/server:2022-latest` (step 3) |

Project gates kept as stricter rules: design check against
`feature/interviewer-portal`, section comparison (blocking once its
`continue-on-error` is removed), screenshot parity (label `screenshots`),
website output and CSP checks, Studio preview design check.

## 4. Security

| Id | Rule | Enforced by | Status |
|---|---|---|---|
| S-1 | The API is the only boundary. The website and Studio reach data only through it. | Architecture; `docs/business-analysis.md` | Met |
| S-2 | Every route has a policy; the fallback requires an authenticated user. | `Program.cs` fallback policy; role matrix in `CareersTests` | Met |
| S-3 | Every security fix ships with its regression test, written red first, and a role-matrix entry when a route is involved. | Review | Partial |
| S-4 | Parameterised data access only (EF Core); validation before the store; redirect paths checked by one rule shared by the API and the website build; no internals in error bodies. | `RedirectPathRuleTests`, Semgrep | Met |
| S-5 | Sessions: the refresh cookie is HttpOnly, Secure, SameSite=Strict; sessions can be revoked; a password reset ends every session. | `TokenService`; `SessionRevocationTests`, `SessionLimitTests`, `SessionCheckTests` | Met |
| S-6 | Secrets only in user-secrets locally and on the host in production; never committed or logged. | gitleaks; `AGENTS.md` | Met |
| S-7 | A Critical or High finding, reachable or not, is fixed within 7 days of being known, or the owner records an exception with an expiry in `docs/deferred-items.md`. | `known-findings.json` (owner, reason) | Gap: no expiry or owner decision recorded (baseline F3) |
| S-8 | The application login reads and writes rows only; the audit log is append-only for it. | `AuditLogPermissionTests`; `docs/security-deployment.md` | Met |

## 6. Baselines and exceptions

- A baseline is taken once, by the pull request that adds its gate, and only
  shrinks after that. A fixed violation is removed from the baseline in the same
  pull request.
- `.github/security/known-findings.json` is the existing baseline for security
  findings. From the next change to it, each entry cites a `D-NNN` id in
  `docs/deferred-items.md` and carries an expiry. Status: Gap (step 4f).
- Every exception is a `D-NNN` entry in `docs/deferred-items.md`: the rule, the
  justification, the owner's words and date, the follow-up owner, the expiry,
  and the follow-up pull request.
- A per-line suppression carries a reason and a reference. No file-wide disables.

## 8. Definition of Done

The ten boxes are in `.github/pull_request_template.md`. Until Phase D there is
no deploy: box 10 records who merges into `rebuild/dotnet-platform` and that the
suites were re-run after the merge (`AGENTS.md`).

## 9. Open owner decisions

Each is asked directly and recorded verbatim when answered.

| Id | Decision | Recommendation |
|---|---|---|
| O-1 | Fix or accept the Critical `next` advisories (baseline F1) | Fix now: upgrade the website to `next@16.4.3` in its own pull request |
| O-2 | Default branch | Make `rebuild/dotnet-platform` the default, so scheduled scans run (F2). `main` stays unchanged. |
| O-3 | Merge method | Keep squash for now, since the integrator re-runs the suites after each merge; revisit with the deploy guard in Phase D |
| O-4 | Production SQL Server version | Record it, and pin CI to the same major version |
| O-5 | Error body | Keep RFC 7807; add `correlationId` to the body (additive) |
| O-6 | Compliance law and contact-enquiry retention | Owner to name them in the profile |
| O-7 | Standing authorisation for routine choices | Owner's own words, recorded once |
